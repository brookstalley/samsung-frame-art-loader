# The label's text rendering: `art.py` imports `cairo` and `gi`. **These two need
# system libraries before pip can build them** — on Raspberry Pi OS:
#
#     sudo apt install python3-dev python3-gi python3-gi-cairo gir1.2-pango-1.0 \
#                      libcairo2-dev libgirepository1.0-dev
#
# Listed here anyway rather than left to setup lore, because this file is what
# `deploy/README.md` points a rebuilt Pi at, and a dependency nothing declares is
# one nobody installs until an import fails.
#
# `python3-dev` is first in that list and is NOT for cairo or gi. Several packages
# here compile C or Cython extensions against the interpreter's headers — `rpi-gpio`
# and `IT8951` among them — and without it a rebuilt Pi fails at
# `fatal error: Python.h: No such file or directory`. Verified on a fresh Trixie
# install 2026-08-04, where the failure surfaced while building `rpi-gpio`: the
# error names whichever extension happens to compile first, which is not
# necessarily the package a reader would go looking in. It is unnecessary on a
# uv-managed standalone interpreter, which carries its own headers — but this file
# targets the display plane, which runs on the system interpreter by design.
pycairo==1.26.1
PyGObject==3.48.2
